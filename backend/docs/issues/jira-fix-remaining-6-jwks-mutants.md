## Problem

The weekly mutation-testing CI run [30189219445](https://github.com/tradem/breakdown-rs/actions/runs/30189219445)
detected 125 surviving mutants. Most were fixed in
`fix/mutation-testing-survivors-weekly-30189219445`, but **6 mutants in
`crates/api/src/auth/jwks.rs`** remain uncatchable by unit tests in the
current test harness:

### Location 1: Cache TTL comparison (line 100)

`CachingJwksProvider::decoding_keys` checks whether the cached JWKS is still
fresh via `cached.fetched_at.elapsed() < self.ttl`. The `<` operator has 3
surviving variants (`==`, `>`, `<=`):

```
MISSED  crates/api/src/auth/jwks.rs:100 — replace < with ==
MISSED  crates/api/src/auth/jwks.rs:100 — replace < with >
MISSED  crates/api/src/auth/jwks.rs:100 — replace < with <=
```

These survive because `Instant::elapsed()` cannot be advanced in unit tests
without time-manipulation infrastructure (cf. `tokio::time::pause()` only
affects async sleep, not `Instant`).

### Location 2: JWK filtering logic (line 123)

The key-filtering predicate `if jwk.kty != "RSA" || jwk.use_.as_deref() == Some("enc")`
has 3 surviving operator variants:

```
MISSED  crates/api/src/auth/jwks.rs:123 — replace || with &&
MISSED  crates/api/src/auth/jwks.rs:123 — replace != with ==
MISSED  crates/api/src/auth/jwks.rs:123 — replace == with !=
```

To catch these a test must serve a JWKS with realistically formatted RSA keys
over HTTP, then call `decoding_keys()`. The `jsonwebtoken::DecodingKey::from_rsa_components`
function rejects RSA keys generated by the `rsa` crate in dev-dependencies under
certain conditions, making a straightforward inline test non-trivial.

## Proposed solution

Two approaches are viable:

### Approach A — Integration test with wiremock

Add `wiremock` or start a local Axum server in an integration test
(`crates/integration-tests/`) that serves a JWKS endpoint with:
- One valid RSA signing key with a `kid`
- One encryption-purpose key (`"use": "enc"`)
- One non-RSA key (`"kty": "EC"`)
- One RSA key without a `kid`

Verify `decoding_keys()` returns exactly 1 key (the valid signing key).

### Approach B — Timed cache test

Use `tokio::time::pause()` + a shortened TTL to force cache expiry between
two calls, verifying the second call re-fetches from the server.

Both approaches require `tokio` time-manipulation features and a controlled
HTTP endpoint.
